---
label: License & provenance
description: Is the license acceptable, and can every bundled piece of code and data be redistributed under it?
when: Before accepting any package, or when it bundles data, vendored code, or code adapted from elsewhere or written with AI.
time: ~30–60 s
---
Check licensing, third-party code and data provenance.

Guidelines: DESCRIPTION `License` (https://contributions.bioconductor.org/description.html#description-license) and the AI policy and third-party code chapter (https://contributions.bioconductor.org/ai-policy-third-party.html). Cite them when you raise a point.

1. **License field.** Read DESCRIPTION. It must be a standard license with its version (e.g. `GPL-3`, `Artistic-2.0`, `MIT + file LICENSE`), or `file LICENSE` with the full terms in that file. Licenses that restrict use are not acceptable: CC BY-NC, CC BY-NC-SA, CC BY-NC-ND, ACM, academic- or non-commercial-only terms (must fix). For `+ file LICENSE` / `file LICENSE`, read the file: is it present, consistent with the field (same license, year and holder for MIT/BSD), and not a different license? Note a stray `LICENSE.md` or license text that contradicts DESCRIPTION.
2. **Third-party and adapted code.** Use search_code and list_files to find code the authors didn't write: vendored libraries in `src/` (whole projects, headers with other copyright lines), JavaScript/CSS/fonts in `inst/` or Shiny `www/`, `inst/python`, and R code with comments like "adapted from", "copied from", "based on", "original code", "Copyright", "Licensed under", "SPDX", or links to GitHub/Stack Overflow. Also stale traces, such as another package's class or function names in messages. For each piece: where it is (permalink), its source, the source's license if stated, whether it can be redistributed under the package's license (e.g. GPL code in an MIT or Artistic-2.0 package is not, unless the package is relicensed), whether it is attributed in the code, and whether its copyright holders are credited (`cph` role in `Authors@R`, or a copyrights file, per Writing R Extensions).
3. **Disclosure.** Non-trivial code copied from elsewhere or generated with AI must be disclosed in the issue with its provenance (`Assisted-by: …` / `Code copied from: …`) and cited in the code. Check the thread for a disclosure. Report concrete signs of undisclosed copied code only, never a hunch about style.
4. **Data.** For everything in `data/`, `inst/extdata`, `tests/` fixtures, and anything vignettes or examples download: where it came from (`inst/scripts`, man page `\source`, README), under what license or terms of use, and whether it may be redistributed. Flag human-subject data without a statement of de-identification and permission to share. For web services or databases the package queries, say whether their terms of use allow the access and any redistribution.
5. **Dependencies.** Only if you know a dependency or `SystemRequirements` tool has non-free or restrictive terms, say so, and say how sure you are. Don't guess.

Reply in chat with one row per item: what, where (permalink), what you found, and a verdict: **OK**, **ask the submitter** (the information is missing), or **must fix** (a restrictive license, or code or data that can't be redistributed). End with the exact questions to ask the submitter. Only report what you checked in the files or the thread, and say when you couldn't find a source or license. If the reviewer asks, add the points to the draft under `## Licensing and provenance` as `- [ ]` items (edit_draft, or write_draft if the draft is empty).
